Telegram Sessions
Руководство пользователя · версия 2.3.0

НАЧАЛО РАБОТЫ
Откройте Telegram Sessions.exe. В настройках укажите собственные API ID и API hash из раздела API development tools на my.telegram.org. Выберите рабочие папки и добавьте файлы .session формата Telethon.

ОБРАБОТКА АККАУНТОВ
Отметьте аккаунты и нажмите «Запустить выбранные». Программа проверит исходную авторизацию, создаст новую, настроит 2FA и проверит сохранённые файлы перед завершением старой сессии. Свежий код входа считывается автоматически при доступности; иначе появится ручной ввод. Пароль 2FA берётся из JSON или запрашивается отдельно.

Новые сессии и парные JSON сохраняются в папках new_sessions\+номер\session\. Исходные файлы после выхода из старой авторизации перемещаются в old/archive. Техническая папка .state нужна для продолжения после прерывания.

КОНВЕРТАЦИЯ
Вкладка «Конвертация» поддерживает .session → tdata и tdata → .session, несколько файлов, папки аккаунтов и ZIP с tdata. Результаты сохраняются в единой папке new_sessions\+номер\: сессии и JSON в session, данные Telegram Desktop в tdata. Если номер неизвестен, программа определит его через API либо запросит ввод.

Конвертация переносит существующую авторизацию в другой формат. Для нового ключа используйте вкладку «Аккаунты». Для создания tdata необходим ID пользователя: из JSON, через API или введённый вручную. Защищённая папка tdata может запросить локальный код Telegram Desktop, отличный от облачного пароля 2FA.

ЛОГИ И ОСТАНОВКА
«Активные задачи» показывает прогресс. «Логи» содержит время и действия по аккаунтам; история сохраняется в run.log. «Остановить» завершает текущий аккаунт и прекращает очередь. После сбоя повторите обработку с теми же папками.

ДАННЫЕ
Рабочие файлы находятся в data рядом с приложением или в выбранных папках. JSON аккаунтов содержит API-данные и открытый пароль 2FA. Ограничьте доступ к этим файлам. Коды и пароли не записываются в журналы. Не запускайте одновременно несколько программ с одной сессией.

Не переносите EXE отдельно: служебные файлы, resources и locales нужны для работы. Храните приложение в папке с правом записи.

КОНТАКТ
Кнопка с иконкой Telegram открывает профиль @Kenjee132.

ЛИЦЕНЗИИ
Лицензии сторонних компонентов поставляются вместе с приложением. Telegram Sessions является независимым приложением и не представляет Telegram.

ВТОРАЯ СЕССИЯ
Кнопка с плюсом в строке аккаунта создаёт новую авторизацию с отдельным ключом, сохраняя исходную сессию. Это новый вход, не копирование файла.

УДАЛЕНИЕ ИЗ СПИСКА
Кнопка с корзиной убирает исходную сессию и JSON в корзину Windows. Готовые результаты сохраняются, авторизации Telegram не завершаются.

ВЕРСИЯ 2.3.0

Переключатель RU/EN в шапке меняет язык интерфейса и сохраняет выбор. Перед новым входом программа пытается завершить все остальные авторизации, включая другие устройства и ранее созданные сессии. Это можно отключить в настройках. Текущая исходная авторизация нужна для входа: при замене она завершается после проверки новой, а в режиме второй сессии сохраняется. Если Telegram запрещает завершение, обработка продолжится с предупреждением в логах и результате. Для авторизаций младше 24 часов Telegram запрещает такой сброс.

Новые файлы называются +номер.session и +номер.json. Дополнительные авторизации с тем же номером размещаются в session/2/, session/3/ и далее. JSON использует поля app_id, app_hash, twoFA, данные профиля и session_file (имя без расширения). Состояние обработки хранится отдельно в .state.

ВЕРСИЯ 2.3.0: SESSION И TDATA ВМЕСТЕ

После обычной переавторизации и создания второй сессии сохраняются оба формата. Tdata повторно открывается и проверяется до выхода из исходной сессии. При ошибке экспорта исходная авторизация сохраняется, а новый файл сессии остаётся для повтора. Для уже обработанного аккаунта повторный запуск создаёт недостающую tdata без нового входа.

Во вкладке «Конвертация» кнопка «Выбрать аккаунты» добавляет импортированные аккаунты в очередь. Опция «Создать новую сессию перед конвертацией» выполняет новый вход и сохраняет проверенные .session и tdata. Без этой опции конвертация сохраняет текущую авторизацию. Для нового входа нужны API ID/hash; при необходимости программа запросит код или пароль 2FA.
