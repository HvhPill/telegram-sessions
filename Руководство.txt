Telegram Sessions
Руководство пользователя · версия 2.0.0

НАЧАЛО РАБОТЫ
Откройте Telegram Sessions.exe. В настройках укажите собственные API ID и API hash из раздела API development tools на my.telegram.org. Выберите рабочие папки и добавьте файлы .session формата Telethon.

ОБРАБОТКА АККАУНТОВ
Отметьте аккаунты и нажмите «Запустить выбранные». Программа проверит исходную авторизацию, создаст новую, настроит 2FA и проверит сохранённые файлы перед завершением старой сессии. Свежий код входа считывается автоматически при доступности; иначе появится ручной ввод. Пароль 2FA берётся из JSON или запрашивается отдельно.

Новые сессии и парные JSON сохраняются в папках new_sessions\+номер\. Исходные файлы после выхода из старой авторизации перемещаются в old/archive. Техническая папка .state нужна для продолжения после прерывания.

КОНВЕРТАЦИЯ
Вкладка «Конвертация» поддерживает .session → tdata и tdata → .session, несколько файлов, папки аккаунтов и ZIP с tdata. Результаты сохраняются в conversions. Когда номер телефона неизвестен, используется ID аккаунта.

Конвертация переносит существующую авторизацию в другой формат. Для нового ключа используйте вкладку «Аккаунты». Для создания tdata необходим ID пользователя: из JSON, через API или введённый вручную. Защищённая папка tdata может запросить локальный код Telegram Desktop, отличный от облачного пароля 2FA.

ЛОГИ И ОСТАНОВКА
«Активные задачи» показывает прогресс. «Логи» содержит время и действия по аккаунтам; история сохраняется в run.log. «Остановить» завершает текущий аккаунт и прекращает очередь. После сбоя повторите обработку с теми же папками.

ДАННЫЕ
Рабочие файлы находятся в data рядом с приложением или в выбранных папках. JSON аккаунтов содержит API-данные и открытый пароль 2FA. Ограничьте доступ к этим файлам. Коды и пароли не записываются в журналы. Не запускайте одновременно несколько программ с одной сессией.

Не переносите EXE отдельно: служебные файлы, resources и locales нужны для работы. Храните приложение в папке с правом записи.
